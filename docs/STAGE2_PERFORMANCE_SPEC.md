# STAGE2_PERFORMANCE_SPEC.md — 2단계 성과검증 설계 (초안, 미확정)

작성일: 2026-07-05
최종 수정: 2026-07-05 (1차 읽기 기반 구현 완료 — 종목 성과검증 + 오늘 추천 없음 평가)
상태: **1차 구현 완료** (`price_data.py`, `performance.py`, `app.py` 성과검증 탭:
종목 성과검증 표 + "오늘 추천 없음 평가" 섹션 + CSV 내보내기 2종).

## 1차 구현 메모 (2026-07-05)

- **반도체 판정**: `market=US`인 종목 중 화이트리스트(NVDA, MU, TSM, AMD, INTC, AVGO,
  QCOM, ASML, AMAT, LRCX, KLAC, ON, SOXX, SMH)에 있으면 SOXX, 아니면 SPY로 자동 결정
  (`performance.py`의 `SEMICONDUCTOR_TICKERS`). 사람이 매번 고르지 않는다.
- **"초과수익률" 단일 컬럼**의 기준: 3번 항목에서 정한 "5일 대표값" 규칙을 그대로 적용해
  **5일 수익률 기준 초과수익률**로 계산한다. 1/3/10/20일용 초과수익률은 1차에서 별도
  컬럼으로 만들지 않았다 (필요하면 다음 단계에서 추가).
- **`market=OTHER`**: 기준지수를 결정할 수 없으므로 상태를 "데이터 부족"으로 처리한다.
- **상태 판정 기준**: 티커 없음/OTHER/기준지수 조회 실패/종목 시세 조회 실패 → "데이터
  부족", 진입일 자체를 아직 특정할 수 없음(너무 최근 저장) → "대기", 진입가를 찾았고
  1개 이상의 기간 수익률을 계산함 → "계산 완료" (계산 완료 상태에서도 아직 시간이 안 지난
  긴 기간은 개별 셀에 "-"로 표시될 수 있음).
- **데이터 소스**: `yfinance` 우선, 실패 시 `FinanceDataReader` 보조. `pykrx`는 1차에
  사용하지 않음(계획대로).
- KOSPI/KOSDAQ 분리, KOSDAQ 실제 지원은 이번 1차에도 미구현 상태 그대로.
- **오늘 추천 없음 평가(1차)**: `report_items`가 0개인 report만 대상. `market_scope=KR`
  → KOSPI 1건, `US` → SPY 1건, `MIXED` → KOSPI/SPY 각각 1건(총 2건)으로 분리 표시.
  진입 기준은 종목 성과검증과 동일한 규칙(`determine_entry_rule`)을 report의
  `timing_class`에 적용해서 사용한다. 판정("기회비용"/"위험회피 성공"/"보합")은 **5일
  수익률 기준**으로만 대표 표시하고(종목 표와 동일한 대표 기간 규칙), 1/3/10/20일 값은
  참고용 수익률로 함께 노출한다. 수익률이 정확히 0%인 경우는 "보합"으로 별도 표기한다
  (기회비용도 위험회피 성공도 아님).

## 1. 2단계 목표

- 저장된 브리핑의 종목 판정(추천 후보 / 감시 / 확인 필요 / 보류(선반영) / 제외)이
  **실제로 맞았는지** 사후에 검증한다.
- 이것은 **자동매매가 아니라 사후 검증 성적표**다. 실시간 신호, 매수/매도 판단,
  주문 실행과는 전혀 무관하다.
- 목적은 "GPT 브리핑이 얼마나 신뢰할 만한가"를 데이터로 축적하는 것이지,
  이 프로그램을 통해 매매를 유도하거나 자동화하는 것이 아니다.

## 2. 진입가 규칙

종목 판정이 내려진 시점(`item_timing_class` 또는 report의 `timing_class`)에 따라
비교 시작 가격(기준가)을 다르게 잡는다.

| 판단 시점 | 기준가 |
|---|---|
| 장전 | 그날 시가 |
| 장중 | 그날 종가 |
| 장후 | 다음 거래일 시가 |

- **판단 시각 이전 가격은 절대 사용하지 않는다.** (미래 정보를 과거 판단에 끌어다 쓰는
  룩어헤드 편향 방지 — 예: 장전 판단인데 전날 종가를 기준가로 쓰면 안 됨)
- 휴장일(주말/공휴일)에 저장된 브리핑은 "다음 거래일"을 기준으로 위 표를 적용한다
  (세부 캘린더 처리 방식은 코딩 단계에서 결정).

## 3. 검증 기간 — 확정

기준가 대비 아래 5개 시점의 가격을 **전부 계산**한다 (모두 거래일 기준. 캘린더일 아님).

- 1일 후
- 3일 후
- 5일 후
- 10일 후
- 20일 후

- **계산은 5개 기간 전부** 수행한다 (생략 없음).
- 다만 **요약 화면(오늘의 결론 탭 등)에서는 5일 기준을 대표값으로 먼저 보여준다.**
  나머지 1/3/10/20일 값은 상세 화면이나 펼침(expander) 등에서 확인 가능하게 한다.
- "오늘 추천 없음"의 기회비용/위험회피 판단도 동일하게 **5개 기간 전부 계산**하고,
  요약에는 5일 기준을 대표로 노출한다 (6번 참고).

## 4. 비교 기준 (벤치마크 지수) — 확정

| 종목 구분 | 비교 지수 | 상태 |
|---|---|---|
| 한국 종목 (1차) | **KOSPI로 통일** | 확정 |
| 한국 종목 (KOSDAQ, 향후) | KOSDAQ (설계 여지만 남김, 지금은 미적용) | 보류 |
| 미국 반도체 종목 (NVDA, MU, TSM, AMD 등) | **SOXX 기본**, QQQ는 보조 비교로만 사용 | 확정 |
| 미국 반도체 외 종목 | **SPY 기본**, QQQ는 기술주/나스닥 성격이 강한 종목의 보조 비교로만 사용 | 확정 |

- **한국 종목**: 1차는 종목의 `market`이 KR이면 무조건 KOSPI를 기준지수로 쓴다.
  다만 `report_items.market`이 KOSDAQ으로 입력된 경우를 대비해, 기준지수 결정 로직은
  "종목의 market 값 → 기준지수" 매핑 형태로 설계해서 나중에 KOSDAQ 분기를 추가하기 쉽게
  여지만 남긴다. **지금 코딩 단계에서는 KOSDAQ 분기를 실제로 만들지 않고 전부 KOSPI로
  처리한다.**
- **미국 반도체 종목**: NVDA, MU, TSM, AMD 등 반도체 관련 종목은 SOXX를 기본 비교지수로
  쓴다. QQQ는 참고용 보조 비교지수로만 함께 표기하되, 성공/실패 판정의 기준은 SOXX다.
- **미국 반도체 외 종목**(예: 일반 빅테크, 소비재, 금융 등): **SPY를 기본 비교지수로
  통일**한다. 다만 기술주/나스닥 성격이 강한 종목은 QQQ를 보조 비교지수로 함께 표기할 수
  있다 — 단, 성공/실패 판정의 기준은 어디까지나 SPY다.
- 종목이 반도체인지 아닌지는 사람이 종목 입력 시 `market`/`stock_name`/`ticker`를 보고
  판단하거나, 별도의 반도체 티커 목록(화이트리스트)으로 관리하는 방식이 필요하다
  (구체적 구현 방식은 코딩 단계에서 결정).

## 5. 평가 항목 — 표 분리 확정

종목별로 다음을 계산한다.

- 종목 수익률 (기준가 → N일 후 가격)
- 기준지수 수익률 (같은 기간)
- 초과수익률 (종목 수익률 − 기준지수 수익률)
- 상승/하락 여부 (단순 방향성)
- 추천 후보 성공률 (추천 후보로 분류된 종목들의 초과수익 달성 비율)
- 감시 후보 후속 성과 (감시로 분류된 종목들이 이후 실제로 어떻게 움직였는지 추적)
- 오늘 추천 없음의 기회비용/위험회피 효과 (6번 규칙 참고)

**표 구성 확정**: 판정별로 성과표를 **3갈래**로 나눈다. 절대 섞지 않는다.

1. **추천 후보 성과표**: 추천 후보 성공률(초과수익 기준 성공/실패 비율)을 핵심 지표로
   삼는다.
2. **감시 후보 성과표**: "성공/실패"로 단정하지 않고 "후속 성과 추적"으로만 표기한다
   (감시는 매수 추천이 아니라 관찰 대상이므로, 성공률이라는 표현 자체를 쓰지 않는다).
3. **기타 판정 추적표**: 확인 필요 / 보류(선반영) / 제외 판정을 모아서 별도로 기록한다.
   - 이 표는 **추천 후보 성공률 계산에 절대 포함하지 않는다.**
   - 추천 후보·감시표와 마찬가지로 종목 수익률/기준지수 수익률/초과수익률/방향성은
     계산해서 보여주되, "성공률"이라는 성격의 지표는 부여하지 않고 "추적" 목적으로만
     둔다 (제외 판정처럼 애초에 관심 대상이 아니었던 종목도 있으므로).

## 6. "오늘 추천 없음" 평가 규칙 — 확정

`reports.day_conclusion`에 "추천 없음"으로 기록된 날은 verdict가 없으므로 종목 단위
평가 대상이 아니다. **오늘 추천 없음은 실패가 아니라 "현금 대기 판단"으로 취급**하고,
그날 이후 **해당 시장의 기준지수**(report의 `market_scope`가 KR이면 KOSPI, US면 해당
미국 벤치마크) 움직임으로 다음과 같이 평가한다.

- 기준지수가 상승했다면 → **기회비용** 발생 (쉬어서 놓친 상승분)으로 기록
- 기준지수가 하락했다면 → **위험회피 성공** (쉬어서 손실을 피함)으로 기록
- **지수 상승만으로 이 날의 판단을 "실패"로 자동 처리하지 않는다.** 관망도 유효한
  판단이며, 성공/실패의 이분법이 아니라 기회비용 또는 위험회피라는 별도 축으로 기록한다.

**`market_scope`별 기준지수 — 확정**

| market_scope | 기준지수 |
|---|---|
| KR | KOSPI |
| US (일반) | SPY |
| US (반도체 관련 섹터/종목 언급) | SOXX |
| MIXED | KR/US를 **각각 따로** 계산 (아래 설명 참고) |

- **MIXED report는 KR과 US를 하나로 억지로 합치지 않는다.** KOSPI 기준 결과와 US
  기준(SPY, 반도체 섹터가 언급된 경우 SOXX 포함) 결과를 **각각 따로 계산해서 나란히
  기록**한다.
- 즉 MIXED report의 "오늘 추천 없음"은 "기회비용/위험회피가 하나의 결론"이 아니라
  **"KR 기준으로는 O, US 기준으로는 O"** 형태의 **시장별 병기**로 표시한다.

## 7. 금지 사항 (2단계에도 동일하게 적용)

- 자동매매 금지
- 매수/매도 신호 생성 금지
- 증권사 API 사용 금지

## 8. 결정 사항 — 전부 확정

- [x] 한국 종목 기준지수: **1차는 KOSPI로 통일**. KOSDAQ 분리는 설계 여지만 남기고
      지금은 구현하지 않는다.
- [x] 미국 반도체 종목(NVDA, MU, TSM, AMD 등)의 기본 비교 지수: **SOXX 고정**, QQQ는
      보조 비교로만 사용.
- [x] **감시** 판정은 추천 후보와 **분리된 별도 성과표**로 관리한다 (5번 참고).
- [x] "오늘 추천 없음"은 **현금 대기 판단**으로 취급하고, 해당 시장 기준지수 상승 시
      기회비용, 하락 시 위험회피 성공으로 기록한다. 지수 상승만으로 자동 실패 처리하지
      않는다 (6번 참고).
- [x] **반도체가 아닌 일반 미국 종목**의 기본 비교지수는 **SPY로 통일**. QQQ는 기술주/
      나스닥 성격이 강한 종목의 보조 비교지수로만 사용 (4번 참고).
- [x] `market_scope=MIXED`인 report는 **KR(KOSPI)과 US(SPY/SOXX)를 하나로 합치지 않고
      각각 따로 계산해서 병기**한다 (6번 참고).
- [x] 검증 기간 5종(1/3/5/10/20일)은 **전부 계산**하되, **요약 화면에서는 5일을 대표값**
      으로 먼저 보여준다 (3번 참고).
- [x] 확인 필요 / 보류(선반영) / 제외 판정은 추천 후보·감시 표와 분리된 **"기타 판정
      추적표"**로 별도 기록하며, **추천 후보 성공률 계산에는 포함하지 않는다** (5번 참고).

**8개 항목이 모두 확정되었으므로, 이제 `database.py`에 어떤 테이블/컬럼이 추가로
필요한지, `app.py`에 어떤 화면 구성이 필요한지 설계로 넘어갈 수 있는 상태다.
단, 코딩은 사용자의 명시적 승인 이후에 시작한다.**
