## 파일과 분리 경계

- `pages/7_자비스7.py`: 독립 로그인·화면 게이트, 컴포넌트 등록, 이벤트 처리.
- `jarvis7_app.py`: 화면 구성·기존 자료 매핑. 다른 페이지 렌더러를 가져오지 않는다.
- `jarvis7_ui.py`: `.j7-shell` 안의 디자인, SVG, 컴포넌트 이벤트와 폴링.
- `jarvis7_data.py`: 자비스7 전용 비동기 조회·중복 요청 통합·캐시.
- `jarvis7_store.py`: 자비스7 관심종목 저장. 처음에는 자비스3 설정을 SELECT로 읽고,
  변경은 `jarvis7_settings`에만 기록한다. 기존 설정·보고서는 수정하지 않는다.
- `mobile_ui.py`: `jarvis7_css()`를 새 화면에서만 호출한다. 폰 규칙은 모두
  `@media (max-width: 600px)` 안에 있다.
- `app.py`, `page_access.py`: 자비스7 메뉴와 접근 등록만 추가했다.

자비스3 페이지·`jarvis3_data.py`·자비스6 페이지·`price_data.py`·`performance.py`는
작업 전 Git 버전과 차이가 없다. `app.py` 수정 전 백업은
`backups/app_20260908_100738.py`이다.

## 속도 개선 방법

1. 첫 화면은 네트워크 결과를 기다리지 않고 그린다. 자료 도착 시 해당 내용을 채운다.
2. 같은 입력의 조회는 실행 중인 작업 하나를 공유한다. 작업자는 3개, 캐시 키는 최대
   96개로 제한해 클릭·새로고침마다 작업이 무한히 쌓이지 않게 했다.
3. 조회 실패 시 마지막 정상 자료를 유지하고 이전 자료임을 표시한다. 관심종목 변경
   이전에 시작된 작업이 나중에 끝나도 변경 후 자료를 덮어쓰지 못하게 했다.
4. 차트는 종목 상세에서 선택한 주기만 요청한다. 홈에서는 뉴스·종목 상세·전체 후보
   심사를 실행하지 않는다. 대장주 목록도 차트 묶음을 만들지 않는다.
5. 화면 이벤트를 렌더링 전에 반영해 추가 `st.rerun()`을 제거했다. 평상시 약 2분,
   자료 대기 중 약 1.6초 간격으로 확인한다. 숨긴 탭에서는 정기 요청을 중단한다.
6. 갱신 중인 입력값과 펼친 설명을 유지한다. 로고가 아직 없으면 이니셜을 표시한다.

JARVIS3 데이터 모듈의 가격 조회와 계산 함수를 그대로 호출한다. 동일 프로세스에서
공유하는 기존 다운로드 잠금·공급자 캐시를 변경하지 않았다. 따라서 외부 시세 수신
자체나 큰 전략 심사가 항상 빨리 끝난다는 보장은 없으며, 대기 중에도 메뉴를 쓸 수
있도록 만든 개선이다.
